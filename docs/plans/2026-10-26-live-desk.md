# Live DESK Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** add a DESK screen to the DashCount dashboard: risk meters, an Alpaca orders-and-fills blotter with reconciliation, system health and an alerts centre, in the existing pixel theme.

**Architecture:**
- **Pure logic modules** (`risk`, `reconcile`, `health`, `alerts`) turn the bot's files, the broker's data and the settings into plain dataclasses.
- **Background threads** (`broker_feed`, the Ollama check) do all network I/O.
- **`desk.py`** only draws; `app.py` wires it all into a tabbed window.
- **The bot** gains two small, additive outputs (`veto_health`, richer `taken` journal events).

**Tech Stack:** Python 3.12, PySide6 (existing), httpx (existing), pytest; no new dependencies.

**Spec:** `docs/specs/2026-10-26-live-desk-design.md`

## Global Constraints

**Alpaca use**
- The app **never places or cancels orders**: every Alpaca call is an HTTP GET.
- At most 2 Alpaca requests per poll:
  - **Poll timing:** every **10 s** from open − 30 min to close + 30 min, otherwise every **300 s**.
  - **Backoff:** **30 s** after one failure, **60 s** after 2 or more in a row.
  - **HTTP 429:** wait until `X-RateLimit-Reset`.
  - **Timeout:** **5 s** per request.
- Raw JSON only: never use alpaca-py models (they crash on the TXSE exchange).
- No network or process checks on the Qt UI thread.

**Display rules**
- Meter colours by the share of the limit used: `< 0.50` ok (emerald), `0.50–0.75` warn (gold), `>= 0.75` danger (redstone). A snapshot older than **90 s** means level `stale` (greyed out), with the text "bot last seen …".
- Slippage sign: **positive = worse for us**. Shown in $ per share and in R, where R = |planned entry − planned stop|.
- Alert sounds: info → `click`, warn → `taken`, danger → `panic` (existing `Sounds`, off by default).
- Keep the theme: pixel panels from `pixel.py`, uppercase pixel titles, VT323 body text.

**Repository rules**
- Commits must NOT carry a `Co-Authored-By` trailer (user rule); the repo config already sets the author.
- Preserve each file's line endings: edit with the editor tool, not `sed`.
- Never kill the dashboard by image name (`taskkill /IM DashCount.exe` also kills the bot); use a PID.
- Run tests from the worktree root with:
  `PYTHONPATH="$PWD/src" ../../../.venv/Scripts/python.exe -m pytest -p no:cacheprovider <tests>`

## Review Focus

1. **Foreign or older orders:** an order whose `client_order_id` isn't `dc-…`, or whose trade has no journal plan, gets a row with role by order type and slippage `None` (shown "—"). No crash. *(Task 3 test)*
2. **Short trades:** a sell entry filled *below* plan is worse (positive slippage); a buy-to-cover target filled *below* the limit is better (negative). *(Task 3 test)*
3. **Partly filled, then cancelled entries:** show `filled_qty` of `qty` and count as a fill in the summary, not as rejected. *(Task 3 test)*
4. **Starting the app outside market hours** with yesterday's snapshot: the meters are greyed out, the health rows are idle (not red), and there is no alert storm. In particular, no `bot_silent` or `ollama_down` alert outside the session. *(Tasks 5 and 6 tests)*
5. **Restarting the app mid-day:** alerts already in `alerts-<day>.jsonl` are shown and not raised again; old journal trades don't produce new sounds. *(Task 6 test)*

### Task 3: Blotter and reconciliation (`reconcile.py`)

**Files:**
- Create: `src/dashcount_ui/reconcile.py`
- Test: `tests/test_desk.py`

**Interfaces:**
- **Consumes:** Alpaca order JSON from `GET /v2/orders?nested=true`. Numbers come as strings; fields used: `id`, `client_order_id`, `symbol`, `side`, `type`, `qty`, `filled_qty`, `filled_avg_price`, `limit_price`, `stop_price`, `status`, `submitted_at`, `legs`. Also the journal `taken` events from Task 1.
- **Produces:**
  ```python
  @dataclass(frozen=True)
  class BlotterRow:
      order_id: str
      parent_id: str | None    # legs point at their entry's order_id
      ts: float                # submitted_at as epoch seconds
      symbol: str
      side: str                # BUY | SELL
      role: str                # ENTRY | TARGET | STOP | EXIT
      qty: float
      filled_qty: float
      price: float | None      # limit or stop price
      status: str
      fill: float | None
      slip: float | None       # $/share, + = worse for us
      slip_r: float | None
      trade_id: str | None

  def plans_from_journal(entries: list[dict]) -> dict[str, dict]: ...
      # trade_id -> {"entry", "stop", "target", "qty", "direction"}
  def blotter_rows(orders: list[dict], plans: dict[str, dict]) -> list[BlotterRow]: ...
      # oldest first; each entry is followed by its legs
  def blotter_summary(rows: list[BlotterRow]) -> dict: ...
      # {"orders", "fills", "entry_slip_bps", "entry_slip_r", "rejected"}

  class Reconciler:
      def __init__(self, grace_s: float = 30.0): ...
      def update(self, broker_symbols: set[str], bot_symbols: set[str],
                 now: float) -> list[str]: ...
  ```
- **Roles:**
  - A top-level order with legs is an `ENTRY`.
  - A leg with type `limit` is a `TARGET`; a leg with type `stop` or `stop_limit` is a `STOP`.
  - A top-level order without legs is an `EXIT` if a `market` order, otherwise an `ENTRY`.
  - `trade_id` is the entry's `client_order_id` when it starts with `"dc-"`, else `None`. Legs inherit it.
  - An `EXIT` is attached to the latest earlier `ENTRY` of the same symbol: it takes that entry's `parent_id` and `trade_id`, and is listed after the entry's legs. This is the spec's "appears as a leg".
  - Direction comes from the plan, or else from the entry side (`buy` → +1).
- **Slippage (`d` = direction):**
  - ENTRY: `d * (fill - plan.entry)`.
  - TARGET: `d * (price - fill)`.
  - STOP: `d * (price - fill)`. Alpaca's stop leg already carries the moved stop after a checkpoint, which covers the spec's "last planned stop".
  - EXIT, missing plan, or missing fill: `None`. A market exit (count flip, stale, end of day) has no planned price, so "—" is the honest value.
  - `slip_r = slip / abs(plan.entry - plan.stop)`.
- **Reconciler messages:**
  - `"{sym}: held at the broker but unknown to the bot"`
  - `"{sym}: the bot has a trade but the broker has no position"`

  Each is reported only after the mismatch has lasted `grace_s`, and its timer resets when it clears.

      configured: bool

### Task 6: Alerts centre (`alerts.py`)

**Files:**
- Create: `src/dashcount_ui/alerts.py`
- Test: `tests/test_desk.py`

**Interfaces:**
- **Consumes:** `Meter` (Task 2), `BlotterRow` (Task 3), and journal events.
- **Produces:**
  ```python
  @dataclass(frozen=True)
  class Alert:
      ts: float
      id: str
      level: str    # info | warn | danger
      text: str
      key: str      # de-duplication key

  @dataclass
  class AlertInputs:
      in_session: bool
      meters: list[Meter]
      losers_in_row: int
      streak_limit: int
      heartbeat_age: float | None
      held_stale: list[str]
      rejected: list[BlotterRow]
      alpaca_errors_10min: int
      alpaca_ok: bool
      mismatches: list[str]
      ollama_up: bool | None
      guardian: dict
      day: str

  class AlertEngine:
      def __init__(self, folder: Path): ...          # data/state
      def start_day(self, day: str) -> list[Alert]: ...
          # loads alerts-<day>.jsonl (newest first) and seeds the de-duplication memory
      def from_journal(self, entries: list[dict], now: float) -> list[Alert]: ...
          # trade_open / trade_close
      def evaluate(self, now: float, x: AlertInputs) -> list[Alert]: ...
          # new condition alerts
  ```
  Every new alert is appended to `alerts-<day>.jsonl` (one JSON object per line: `ts`, `id`, `level`, `text`, `key`).
- **Rules and exact texts** (`key` = `id` unless stated):

  | id | Level | Fires when | Text |
  |---|---|---|---|
  | `trade_open` | info | per `taken` event; key `trade_open:<trade_id or ts>` | `"{symbol} {LONG/SHORT} opened: {qty} sh at {entry:.2f}"` |
  | `trade_close` | info | per `exit` event; key `trade_close:<ts>:<symbol>` | `"{symbol} closed: {pnl:+.2f} ({r:+.2f}R)"` |
  | `day_loss_50` / `day_loss_75` | warn / danger | Day-loss meter frac ≥ 0.5 / ≥ 0.75 | `"Day loss at 50% of the limit ({meter.text})"` (75% likewise) |
  | `streak_3` | warn | `losers_in_row == streak_limit - 1` | `"{n} losing trades in a row: one more halts the day"` |
  | `fuse_50` / `fuse_75` | warn / danger | Drawdown meter frac ≥ 0.5 / ≥ 0.75 | `"Drawdown at 50% of the fuse ({meter.text})"` (75% likewise) |
  | `bot_silent` | danger | in session and heartbeat age > 60 | `"The bot has been silent for {age:.0f} s"` |
  | `data_stale_held` | danger | per held stock silent > 180 s; key `data_stale_held:<sym>` | `"No data for {sym} (held) for over 3 minutes"` |
  | `order_rejected` | danger | per rejected order; key `order_rejected:<order_id>` | `"Order rejected: {symbol} {side} {qty:g}"` |
  | `alpaca_errors` | warn | ≥ 3 errors in 10 min; re-arms on `alpaca_ok` | `"Alpaca errors: {n} in 10 minutes"` |
  | `mismatch` | danger | per message; key `mismatch:<message>` | the message |
  | `ollama_down` | warn | in session and `ollama_up is False` | `"Ollama is down: Fin-R1 vetoes will be skipped"` |
  | `guardian_stop` | danger | `halted_day == day`, `panic`, or `armed` false | `"Guardian: halted for the day ({halt_reason})"`, `"Guardian: PANIC"` or `"Guardian: fuse blown ({disarm_reason})"` |

- **Condition alerts:** a key fires once while its condition holds, and re-arms once the condition is false on an `evaluate` call.
- **Event alerts:** a key fires once ever per day (memory seeded from the file).
